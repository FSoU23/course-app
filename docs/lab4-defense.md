# ЛР 4 — загрузка жанров по HTTP

Каташинский А.В., 24ПИ2. Тема: «Личная библиотека».

## Что изменилось по сравнению с третьей лабой

Раньше жанр можно было напечатать как произвольный текст. Теперь форма
получает варианты по HTTP и предлагает выбор. Если справочник недоступен,
сохранить книгу нельзя, но текст можно продолжать вводить и отмена работает.
После восстановления сети кнопка «Повторить» загружает жанры, сохраняя черновик.
Все книги по-прежнему живут в состоянии App и сбрасываются после F5.

## Какие файлы показать

| Файл | Что рассказать |
| --- | --- |
| `frontend/public/demo/genres.json` | Семь вариантов с постоянным id и отображаемым name; Vite раздаёт файл как HTTP-ресурс |
| `frontend/src/types/genre.ts` | Тип одного жанра для TypeScript |
| `frontend/src/services/genres.ts` | fetch, response.ok, чтение unknown и проверка данных перед возвратом |
| `frontend/src/hooks/useGenres.ts` | useEffect, состояние загрузки, retry и очистка запроса |
| `frontend/src/components/BookForm.tsx` | select вместо input, сообщения состояний и две проверки доступности сохранения |
| `frontend/src/data/books.ts` | В genre теперь id справочника, остальные поля книг сохранены |
| `frontend/src/pages/BooksPage.tsx`, `BookDetailsPage.tsx` | Названия жанров читаются из того же справочника; при сбое виден код |

`App.tsx`, страницы создания и редактирования продолжают выполнять свои задачи
из третьей лабы. Новый сетевой хук не владеет коллекцией книг и не сохраняет формы.

## Как проходит запрос

1. Открывается `BookForm`, вызывается `useGenres()`.
2. После появления компонента `useEffect` вызывает `getGenres(controller.signal)`.
3. Сервис отправляет GET к `/demo/genres.json`, проверяет HTTP-статус и читает JSON.
4. `parseGenres` убеждается, что получен массив объектов с непустыми строковыми
   id/name, id без крайних пробелов и без повторений. Пустой массив допустим.
5. Хук записывает либо `success` с данными, либо `error` с сообщением.
6. Форма отображает варианты. `option.value` содержит id, текст option — name.
7. Сохранение доступно, только если выбранный id есть в успешно загруженных данных.
8. При уходе очистка делает `active = false` и вызывает `controller.abort()`.

Адрес собирается через `import.meta.env.BASE_URL`, поэтому учитывает base Vite.
`cache: 'no-store'` позволяет получать актуальную версию JSON при новой попытке.
В этом задании сервером для справочника служит Vite; отдельного backend ещё нет.

## Три разных места хранения данных

- `App`: сохранённая в текущем сеансе коллекция `books`.
- `BookForm`: несохранённый ввод `draft` и ошибки полей.
- `useGenres`: результат загрузки жанров `load` и счётчик попыток `attempt`.

`retry()` выставляет loading и увеличивает attempt. Это повторно запускает эффект,
но не вызывает setDraft, onSave и перезагрузку страницы. Поэтому текст остаётся.
Начальный loading задан через useState, а при повторе — в retry; лишний синхронный
setLoad в самом эффекте не требуется.

## Сценарий демонстрации

1. Открыть `/books/new`, показать Network → `genres.json`: метод GET, статус 200,
   массив в Response и инициатор запроса. Выбрать «Роман», заполнить обязательные
   поля и сохранить книгу. Открыть редактирование: выбран тот же жанр.
2. Сначала открыть сайт, затем включить Offline в Network. Через меню открыть
   создание книги: появится ошибка и «Повторить». Заполнить название и заметку.
   Выключить Offline, нажать «Повторить»: справочник загрузится, текст останется.
3. Временно установить `[]` в `frontend/public/demo/genres.json`. Заново открыть
   форму: «Жанров пока нет», выбор и сохранение недоступны. Вернуть массив.
4. По очереди проверить `{}`, `[{"id":1,"name":"Жанр"}]`, `[{"id":"x"}]`
   и `[{"id":"x","name":"Один"},{"id":"x","name":"Другой"}]`.
   Показать ошибку структуры или повторяющихся id, затем восстановить JSON.
5. На Slow 3G открыть форму и уйти к списку до завершения загрузки.
   Показать отменённый запрос; при новом открытии выполняется новый запрос.
6. Удалить вариант `science-fiction` из JSON и открыть редактирование b1:
   старый код остаётся виден, остальные поля не изменены, нужно явно выбрать жанр.
   Восстановить исходный файл и обычную сеть перед сдачей.
7. Проверить отмену изменения жанра, удаление с подтверждением и фильтр статуса.

Изменение файлов может вызвать полную перезагрузку Vite. Для демонстрации
сохранности черновика используйте Offline → Online, не меняя файлы.
Для preview выполнить `npm run build`, `npm run preview`; убедиться, что
`/demo/genres.json` отвечает массивом, и повторить создание/редактирование.

## Ответы на вопросы

1. **Запрос или импорт?** fetch обращается к ресурсу по HTTP во время работы сайта;
   его видно в Network, он может задержаться или завершиться ошибкой. Импорт
   включил бы данные в код сборки и не проверял бы сетевую загрузку.
2. **Зачем response.ok?** fetch сам не считает HTTP 404/500 сетевым исключением.
   Мы проверяем статус и явно создаём ошибку, если ответ неуспешен.
3. **Пустой массив и неверная структура?** `[]` — правильные данные без вариантов,
   а `{}` или объект без name нарушают контракт. У них разные сообщения.
4. **Почему недостаточно as Genre[]?** Утверждение типа не проверяет реальный JSON.
   Принимаем unknown и проверяем значения в выполняющемся коде.
5. **Где живут состояния?** Коллекция — в App, черновик — в BookForm,
   состояние HTTP-запроса — в useGenres.
6. **Что делает очистка эффекта?** Отменяет запрос и запрещает старым then/catch
   менять состояние. Уход со страницы не должен показывать ошибку отмены.
7. **Почему повтор сохраняет ввод?** Меняется только attempt и load внутри хука.
   Форма не размонтируется, её key и draft не меняются.
8. **Зачем хранить id?** Название можно переименовать, сохранив тот же id.
   Например, книга хранит `novel`, а пользователь видит «Роман».

Проверка `canSave` есть и у disabled кнопки, и внутри handleSubmit: даже отправка
формы другим способом не должна сохранить неизвестный жанр. Исчезнувший старый
жанр нельзя незаметно заменять первым вариантом — это выбор пользователя.
