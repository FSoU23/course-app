# ЛР 3 — формы и локальное состояние

Тема: «Личная библиотека». Автор: Каташинский А.В., 24ПИ2.

## Что показать преподавателю

1. На `/books` показать исходные пять книг и предупреждение о временных данных.
2. Добавить «Розовый сад»: автор «Анна Листова», дата `2026-10-12`,
   статус «Запланировано», оценка пустая. Откроется карточка с новым id.
3. Вернуться к списку: книга появилась. Открыть редактирование, изменить статус
   на «Прочитано», оценку на 5 и добавить заметку. URL книги сохраняет прежний id.
4. Снова начать редактирование, изменить название и нажать «Отмена».
   Показать, что сохранённое название осталось прежним.
5. В форме ввести оценку 6: появится ошибка, остальные данные не исчезнут.
   Аналогично проверить пробелы в названии и отсутствие обязательной даты.
6. Выбрать фильтр «Прочитано», показать новую книгу и сбросить фильтр.
7. Нажать удаление, сначала отменить подтверждение, затем подтвердить.
8. Обновить страницу: вернутся исходные записи. Объяснить, почему это ожидаемо.

## Где реализованы требования

| Требование | Реализация |
| --- | --- |
| Общий список в памяти | `frontend/src/App.tsx`, `useState<Book[]>` |
| Тип черновика без id | `BookDraft = Omit<Book, 'id'>` в `types/book.ts` |
| Создание | `createBook`, новый `crypto.randomUUID()` перед обновлением состояния |
| Обновление без изменения id | `updateBook`, новый массив через `map` |
| Удаление по id | `deleteBook`, новый массив через `filter` |
| Общая управляемая форма | `components/BookForm.tsx`, `value` и `onChange` |
| Отдельный несохранённый черновик | локальный `FormDraft`, копия `initialValues` |
| Проверка до сохранения | `handleSubmit`, `preventDefault`, сообщения у полей |
| Новая книга и редактирование | `NewBookPage`, `EditBookPage`, общий `BookForm` |
| Сброс формы при смене id | `key={book.id}` в `EditBookPage` |
| Фильтр и два пустых состояния | `BooksPage`, локальный статус, вычисляемый `visibleBooks` |
| Подтверждение удаления | `window.confirm` в обработчике кнопки подробностей |
| Временное хранение | пояснение в `AppLayout` на всех маршрутах |
| Нежно-розовое оформление | `index.css` (палитра), `App.css` (компоненты и адаптивность) |

## Правила формы

- Название: от 3 до 100 символов после удаления крайних пробелов.
- Автор: непустая строка после удаления крайних пробелов.
- Дата добавления: обязательна; прошлые даты разрешены.
- Оценка: целое число 1–5 или отсутствие оценки (`null`).
- Жанр, описание и заметка необязательны; все поля доступны при редактировании.
- id недоступен для ввода и не меняется при редактировании.

В поле оценки браузер отдаёт строку, поэтому форма хранит её отдельно от типа
`BookDraft`. Пустую строку сохраняем как `null`; непустую преобразуем через `Number`
и проверяем `Number.isFinite`, целочисленность и диапазон. Некорректный числовой
ввод браузера проверяется через `validity.badInput`, чтобы его не принять за пустое поле.
Сужение типа в `isBookRating` позволяет сохранить `BookRating` без `any`.

## Ответы на вопросы

1. **Почему список в App, а черновик в форме?** App не размонтируется при смене
   страницы и хранит единый список для карточек и подробностей. Черновик принадлежит
   конкретной форме и не должен менять сохранённые данные до нажатия «Сохранить».
2. **Чем props отличаются от состояния?** Props передаёт родитель; дочерний компонент
   читает их и вызывает переданные обработчики. Состоянием компонент управляет
   через `useState` и его setter; изменение вызывает обновление интерфейса.
3. **Почему нельзя push или book.title = ...?** Это меняет существующий массив
   или объект. Для React создаём новые значения: spread при добавлении, `map`
   при изменении и `filter` при удалении. Старые снимки состояния остаются неизменными.
4. **Что делает preventDefault?** Отменяет стандартную отправку HTML-формы
   с перезагрузкой страницы. Сохранением управляет обработчик React.
5. **Как работает отмена?** Ввод меняет только копию полей. Кнопка `type="button"`
   выполняет переход без вызова `onSave`; исходная книга остаётся прежней.
6. **Зачем key у формы?** При переходе с одной редактируемой книги на другую
   React создаёт новый экземпляр формы с новым черновиком. Иначе `useState`
   мог бы сохранить значения предыдущего id.
7. **Почему фильтр не заменяет список?** Фильтр вычисляет только отображаемый
   поднабор. Если записать его вместо полного массива, остальные книги потеряются
   и кнопка сброса их уже не вернёт.
8. **Что произойдёт после обновления?** Приложение монтируется заново;
   `useState` получает копии исходных книг. Изменения памяти пропадают,
   потому что постоянное хранилище в ЛР 3 ещё не подключено.
