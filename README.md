# Личная библиотека

Учебное приложение для учёта книг, статусов чтения и личных заметок.
Автор: Каташинский А.В., группа 24ПИ2.
Репозиторий: https://github.com/FSoU23/course-app

## Текущий этап: лабораторная работа № 3

Продолжен проект ЛР 1 и ЛР 2: теперь можно добавлять, просматривать,
редактировать и удалять книги, выставлять оценки, вести заметки и фильтровать
коллекцию по статусу чтения. Создание и редактирование используют одну форму.
Весь интерфейс оформлен в нежно-розовой палитре, включая формы и сообщения об ошибках.

**Данные хранятся только в памяти открытого приложения.** Внутренние переходы
сохраняют изменения, но после обновления страницы восстанавливаются пять
демонстрационных книг из `frontend/src/data/books.ts`. Созданные записи исчезают.
Это поведение соответствует ЛР 3; сервер, Supabase и localStorage не подключены.
Пояснение о временном хранении видно на каждой странице.

Обязательны название (3–100 символов после `trim`), автор и дата добавления.
Оценка необязательна: допускается только целое число от 1 до 5; пустое поле
сохраняется как `null`. При ошибке введённые данные остаются в форме.
«Отмена» возвращает к списку при создании или к книге при редактировании,
не сохраняя черновик. Удаление требует подтверждения.

## Среда и запуск

Node.js 22.20.0 (зафиксирован в `.node-version`), npm 10.9.3.
Git в окружении ЛР 1: 2.50.1.windows.1.
Основной сценарий: фильтрация, добавление и редактирование книг, заметки и оценки.
React + TypeScript + Vite, React Router 7.18.4 (декларативный режим), CSS.
Точные версии зависимостей фиксирует `frontend/package-lock.json`.

Из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:5173).
Для остановки сервера нажмите Ctrl+C.

Из папки `frontend`:

```bash
npm run lint
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist`; preview обычно доступен на
http://localhost:4173. Используйте фактический порт из терминала.
При будущем размещении на хостинге потребуется возврат `index.html` для SPA-маршрутов.

## Страницы

| Адрес | Назначение |
| --- | --- |
| `/` | Перенаправление на `/books` с заменой записи истории |
| `/books` | Текущая коллекция и фильтр по статусу со сбросом |
| `/books/:id` | Подробности, ссылка на редактирование, удаление с подтверждением |
| `/books/new` | Создание книги |
| `/books/:id/edit` | Редактирование всех содержательных полей книги |
| `/books/missing` | Сообщение «Книга не найдена» |
| `/books/missing/edit` | Отсутствующая книга для редактирования |
| `/unknown` | Сообщение «Страница не найдена» |

## Структура

- `frontend/src/types/book.ts` — Book, BookDraft без id, статусы, оценка и русские подписи.
- `frontend/src/data/books.ts` — начальные демонстрационные данные, импортируются только в App.
- `frontend/src/components/BookCard.tsx` — карточка с типизированными props.
- `frontend/src/components/BookForm.tsx` — общая управляемая форма, отдельный черновик и валидация.
- `frontend/src/pages/` — список с фильтром, подробности, создание, редактирование и неизвестный адрес.
- `frontend/src/app/AppLayout.tsx` — общая шапка, NavLink, Outlet и пояснение о хранении.
- `frontend/src/App.tsx` — общий список в useState, неизменяемые CRUD-обновления и маршруты.
- `frontend/src/index.css`, `frontend/src/App.css` — розовая палитра и адаптивные стили.
- `frontend/src/main.tsx` — единственный BrowserRouter внутри StrictMode.
- `docs/progress.md` — результаты этапов и проверок.
- `docs/lab3-defense.md` — демонстрация, соответствие методичке и ответы для защиты ЛР 3.

## Повторение проверки

До последнего пункта работайте в одной вкладке без обновления страницы.

1. Откройте `/`: появятся пять книг. Добавьте книгу с названием, автором и датой;
   оставьте оценку пустой. После сохранения откроется новая книга, в списке будет шесть записей.
2. Измените название, автора, статус, оценку и заметку. Проверьте новые значения
   в подробностях и списке; id в адресе должен остаться прежним.
3. Повторно измените поля и нажмите «Отмена»: сохранённая книга не изменится.
   Отмените создание другой книги: число записей не увеличится.
4. Проверьте пустое/пробельное название, 2 и 101 символ, отсутствие автора и даты,
   оценки 0, 6, -1 и 2.5. Ошибки видны рядом с полями; введённые данные сохраняются.
5. Выберите статус и сбросьте фильтр. Чтобы получить отсутствие совпадений,
   измените статус единственной книги «Читаю» и снова выберите этот фильтр.
6. Создайте две книги с одинаковым названием. Отмените удаление одной, затем
   подтвердите: удаляется только выбранный id. Вторая книга остаётся.
7. Откройте удалённую книгу через историю браузера, `/books/missing/edit` и
   `/unknown`: появятся соответствующие сообщения. Новая загрузка адреса начинает
   новый сеанс; для проверки удаления демонстрационной книги не обновляйте документ.
8. Удалите все записи: появится «Книг пока нет» со ссылкой добавления первой книги.
   Создайте книгу из пустого списка.
9. Проверьте формы разных книг, сохранение через Enter, отмену без submit,
   видимый фокус Tab и ширины 320/360 px. Внутренние переходы не загружают новый
   Document; консоль не содержит ошибок и предупреждений React.
10. Обновите страницу: исходные пять книг восстановятся. Для нового id появится
    «Книга не найдена». В preview повторите создание, редактирование и отмену.

Для проверки воспроизводимости в чистой копии исходников выполните из `frontend`
`npm ci`, `npm run lint`, `npm run build`.

`node_modules`, `dist`, локальные переменные среды и временные проверки исключены из Git.

## Контрольные вопросы и ответы (Защита ЛР 1)

### 1. Как связаны index.html, main.tsx и App.tsx?
- **index.html** — главная точка входа браузера; содержит контейнер `<div id="root"></div>` и разметку страницы, где подключается скрипт `/src/main.tsx`.
- **main.tsx** — точка входа React-приложения; находит DOM-элемент `#root` и с помощью метода `createRoot` монтирует в него базовый компонент `<App/>`.
- **App.tsx** — главный React-компонент, который описывает структуру, логику и пользовательский интерфейс стартового экрана.

### 2. Чем JSX отличается от обычной HTML-разметки?
- **JSX** — синтаксическое расширение JavaScript. В отличие от HTML:
  - Позволяет внедрять любые JS-выражения прямо в разметку через фигурные скобки `{}`.
  - Использует наименования атрибутов в стиле camelCase (например, `className` вместо `class`, `htmlFor` вместо `for`).
  - Требует обязательного закрытия всех элементов, включая одиночные теги (например, `<br />`, `<img />`).

### 3. Какую ошибку в вашем проекте обнаруживает TypeScript?
- **TypeScript** выполняет статическую проверку типов до запуска кода. Если переменной `appTitle` с явным типом `string` присвоить число (`const appTitle: string = 123`), компилятор `tsc` зафиксирует ошибку несовместимости типов и заблокирует сборку проекта (`npm run build`).

### 4. Чем отличаются dev, build и preview?
- **npm run dev** — запускает локальный сервер разработки с быстрой перезагрузкой изменений в реальном времени (Hot Module Replacement).
- **npm run build** — компилирует TypeScript в JavaScript и собирает оптимизированный продакшн-код в папку `dist/`.
- **npm run preview** — поднимает локальный веб-сервер для проверки собранных файлов из папки `dist/` перед деплоем.

### 5. Зачем нужен package-lock.json и почему node_modules не хранится в Git?
- **package-lock.json** — фиксирует точные версии всех установленных пакетов и их зависимостей. Это гарантирует одинаковую сборку на любом ПК при установке через `npm ci`.
- **node_modules** — не хранится в Git из-за большого размера и динамической природы. Она исключается через `.gitignore` и за секунды восстанавливается с помощью команды `npm ci`.

### 6. Чем отличаются commit и push?
- **git commit** — сохраняет подготовленные изменения как новую точечную запись (снимок) в истории **локального** репозитория.
- **git push** — выгружает накопленные локальные коммиты на **удалённый** сервер (например, GitHub).
